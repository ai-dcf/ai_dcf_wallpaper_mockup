# mjcn.club/app/ (壁纸样机生成器) 1:1 克隆实现计划

## 1. 目标摘要 (Summary)
用户希望对 `https://mjcn.club/app/`（一个基于 Web 的壁纸样机生成器）进行 1:1 克隆。经过分析，原站采用了 Vue 3 + Vite + TailwindCSS + Ant Design Vue 的技术栈，但核心代码经过 `javascript-obfuscator` 深度混淆并包含严格的域名锁定（Domain Lock）机制。
根据用户的选择，我们将采取**“源码重构”**的方案：即使用相同的现代前端技术栈，从零开始重写该应用的 UI 布局与核心样机合成逻辑，最终交付一份完全开源、可二次开发维护的源代码。

## 2. 当前状态分析 (Current State Analysis)
- 原站主要功能包括：丰富的样机模板选择（iPhone、iPad、Mac等）、背景自定义（图片、渐变、纯色、透明）、图片上传与裁切、样机效果实时预览、以及高清图片导出。
- 前端技术特征：DOM 结构由 Vue 3 动态渲染，样式强依赖 Tailwind CSS 实用类，交互组件多采用 Ant Design Vue。
- 核心难点：样机合成逻辑（通常是通过 CSS 绝对定位将“设备边框 PNG”覆盖在“用户上传的壁纸”之上，外层再包裹自定义背景），以及最终结果的导出（DOM 转图片）。

## 3. 提议的变更与实现步骤 (Proposed Changes)

我们将分阶段实现该应用的 1:1 源码级复刻：

### 阶段一：项目初始化与基础设施搭建
- **创建项目**：使用 `npm create vite@latest` 初始化 Vue 3 + TypeScript 项目。
- **配置依赖**：安装并配置 `tailwindcss`、`postcss`、`autoprefixer`。
- **UI 组件库**：集成 `ant-design-vue`，并引入相关 Icon 库。
- **状态管理**：引入 `pinia` 用于全局管理用户当前选择的模板、上传的图片、以及背景设置。

### 阶段二：UI 界面布局还原 (1:1 视觉复刻)
- **整体框架**：构建经典的“左-中-右”或“顶-中-侧”工作台布局：
  - **左侧/顶部区域 (Template Selector)**：实现模板分类切换与缩略图列表（默认、无界、炫光、侧立等）。
  - **中间区域 (Preview Canvas)**：核心预览区，支持缩放、居中显示当前的合成效果。
  - **右侧区域 (Settings Panel)**：配置面板，包含背景类型切换（Radio组件）、颜色/渐变选择器、图片上传/拖拽区域（Upload组件）、裁切按钮及其他功能开关（Switch组件）。

### 阶段三：核心样机合成引擎实现
- **数据结构设计**：定义一套可扩展的模板 JSON 配置规范。例如每个模板包含：`id`, `name`, `frameImg` (边框图URL), `screenWidth`, `screenHeight`, `screenOffsetX`, `screenOffsetY`, `zIndex` 等，确保能精准适配不同机型。
- **渲染逻辑**：在中间预览区，利用 CSS 的 `position: relative/absolute` 与 `z-index`，将用户图片精准嵌入到设备边框图的对应透明区域下（或上）。
- **背景处理**：实现背景层的动态样式绑定（`background-color`, `background-image: linear-gradient(...)` 等）。

### 阶段四：导出与功能完善
- **图片导出功能**：集成 `html2canvas` 或 `dom-to-image-more` 库，将预览区 DOM 节点完整截取并生成高清 PNG/JPG 供用户下载。
- **图片裁切**：集成 `cropperjs` 或 `vue-cropper` 实现上传图片的比例裁切。
- **模板数据填充**：初步内置 3-5 个高精度的样机模板数据（如 iPhone 默认、Mac 桌面等），跑通流程，确保代码结构支持后续轻松批量录入其余几十个模板。

## 4. 假设与决策 (Assumptions & Decisions)
- **模板资源获取**：原站拥有上百个模板，我们将在代码中实现完美的**底层支持引擎**并提供几个示例模板。完整的一百多个模板素材（边框透明PNG图）需要用户后续从原站手动提取或自行准备并按照 JSON 格式填入即可。
- **导出方案**：原站支持导出视频（如动态壁纸），此功能相对复杂，第一版将重点确保“静态高清图片”的 1:1 完美导出，视频导出留作后续扩展接口。
- **技术栈对齐**：为了最大程度降低重构时的样式差异，直接复用原站的 TailwindCSS 模式。

## 5. 验证步骤 (Verification)
1. 运行 `npm run dev` 启动本地开发服务器。
2. 验证左侧模板列表是否可点击切换，并在中间区域实时响应。
3. 验证右侧面板的“图片上传”与“背景颜色更改”是否能正确改变中间预览区的内容。
4. 验证点击“保存/导出”按钮后，能否成功下载一张包含样机边框、用户壁纸、自定义背景的高清合成图。
